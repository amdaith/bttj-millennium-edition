Universal Content - Extracting the Essence

Our approach to the problem

The UC system has been designed to be a scalable system comprising three components. The first component, the Re-purposing engine, employs an Extensible Markup Language (XML) metadata schema to provide content that has been enhanced with additional information. We have used the XML standard developed by the World Wide Web Consortium (W3C) [2] in all our content re-purposing work. This metadata is subsequently used to generate the alternative content required for each user profile. A 'Client Profiler' is the second component, and this determines an appropriate profile that matches the client hardware and network capabilities. The final component is a proxy server around which the UC system is based. In this component a suitable level of content media, produced by the Re-purposing engine, is matched to an appropriate client profile and delivered to the client.
 

Fig 3. The three components in the UC system

The metadata information used by the content re-purposer can be generated automatically by the UC system from the original source content. The primary method we have employed for generating metadata tags for content is to use the description for each item held in its 'alt' tag. Standards bodies, such as the World Wide Web Consortium (W3C) are strongly recommending that Web authors utilise this 'alt' tag whenever possible [3]. It is readily apparent that Web sites that incorporate meaningful metadata in the form of 'alt' tags can be re-purposed by our system for a range of client devices with negligible human adjustment.

Although our system attempts to generate alternative representations of the content, there is no substitute for fine-tuning by the content author / provider. To satisfy this requirement the UC system contains an 'Authoring Tool'. This tool allows the content author to view the generated alternative content for the various client profiles and make adjustments where necessary.

Our metadata will contain details of alternative representations of the content but, in addition, it may contain information on its relative importance. A Website may have an associated audio file which, if it contained background music, would be of minimal importance when compared with a speech file, which could be the main focus of the site. Whilst it is possible within the UC system to make assumptions about the content automatically, the system is most effective when the author provides this information personally at the time of creation.

Maintaining the usability and functionality of the content after re-purposing is another key concept with UC. Traditionally, if users wish to speed up the download of a highly graphical Web page then they may choose to switch off the image option in their browser. Although this may achieve the desired result in speeding up the access speed there are associated drawbacks, for example loss of navigation from image-maps. In this case the user may be left with no means of navigating the site, rendering it useless. In contrast by using the UC system an alternative list of text links can be generated automatically, with meaningful descriptions, for clients who can not, or choose not to, display images.

In this example we have an MPEG video of a daily weather forecast along with a JPEG image of the current weather chart and a text synopsis as the default. There are two alternative provisions which provide a content level appropriate to the target client device profile.

Fig 5. XML to HTML Conversion

In the above animation the conversion to XML process is illustrated. The source HTML page is rendered through a parser into a tree like structure of Java objects. We break the content into logically grouped objects in order to ensure compatibility under each client profile.

These objects are taken by the AutoAuthoring Engine which adds adapted the content for each client profile. This can be output directly as an XML file (ready to be interpreted by an appropriate XSL stylesheet) or it can be passed to the Authoring Tool for fine-tuning by the content provider or author.

A Client Profiler is a key component in the UC system as one of our objectives in designing our system was to produce an appropriate level of content to the client as seamlessly and transparently as possible. In order to prove the concept of our system we have implemented an IP-address based client profiler into the UC proxy server. Although this is not a workable long-term solution it has allowed us to test our re-purposed content to a wide variety of client devices. Other methods for selecting profiles are under evaluation.

 

Fig 6. UC Content Request & Retrieval Mechanism

The proxy server based UC engine is the intelligence of our system. This component is responsible for extracting appropriate content from the enhanced metadata corresponding to the current user profile. This has been implemented as a proxy server which operates in the network by filtering the information received by the client from the information provider.
