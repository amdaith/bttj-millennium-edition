Universal Content - Extracting the Essence

What have we discovered in designing the UC system?

Whilst work on the client profiling component of the UC system is still in its infancy, work on this will be of prime importance in the near future. We have tested the UC 'Automatic Authoring Engine' on both pre-authored and randomly selected existing Web pages.

One of the biggest problems we have encountered is poor HTML authoring. Our Automatic Authoring Engine parses the requested HTML source and tries to disseminate this as a treelike structure of logically grouped objects. Problems occur where the source HTML lacks cohesion or is formatted incorrectly. Generally this is not a problem in that Web browsers are now very sophisticated and can deal with incorrect or poorly formatted HTML, but, when you try to reconstruct the adapted source this can produce errors. One example of this occurs when dealing with image maps. There are usually two parts to the HTML code for image maps, the image details and the links. If these occur sequentially, and have a logically cohesive bonding, then there is no problem processing and reconstructing some format of the image map. Unfortunately most sites have little or no logical ordering and this requires much more intensive processing.

As mentioned earlier the usage of 'alt' tags by HTML authors for every media object can produce an accurate representation of the original source without the need for additional fine-tuning by the content provider. If the HTML authors were to provide, for example, a meaningful description for each image on their site, then meaningful alternatives can be simply produced. In our system an image with no 'alt' tag may have to be reproduced with the textual description '[image]' unless the content provider can fine-tune the content for the affected (in this case low capability) client profile. Our investigations in this area have strongly agreed with the guidelines produced by the W3C in their document 'Web Content Accessibility Guidelines' [3].

Examples of Web pages that try to automatically replace images with text, frequently lose the 'look and feel' of the original and suffer as a consequence, to the point where some are virtually unusable. By using UC we are able to overcome this problem on the majority of Web pages we have tested, as one of our goals was to retain the original design layout, despite the adaptation of the content, for each client profile. This is very important as the positioning of links and media frequently has a direct impact on the site's usability. By maintaining a consistent layout across each client profile the UC system is able to ensure that the client will recognise intuitively the Web page despite any adaptation in the content.

In our system the proxy server can accept either HTML or pre-authored UC files (files that have been passed through the UC Authoring Tool and stored as XML). This means that there is a vastly improved performance with UC files as there is only one conversion process (XML to HTML) as opposed to an HTML to XML to HTML conversion with pure HTML source. This problem could be alleviated somewhat if a caching mechanism to cache heavily used content is incorporated in the proxy server.

The UC system employs XSL Stylesheets to interpret the adapted XML File. Each of these stylesheets is representative of a unique client profile and can produce content as either Wireless Markup Language (WML) (for Wireless Application Protocol (WAP) devices) or VoxML (for Voice devices) in addition to the default HTML output. One of the biggest problem areas is how to process JavaScript and Java applets. In our system we simply turn Java applets or script on or off, depending upon whether the client device is Java enabled. In future development we hope to extend this capability to make decisions on whether or not these Java items are important based upon metadata provided by the Java developer.

The ability to process HTML frames is of major importance to any work on content re-purposing. With Universal Content we can re-purpose the currently displayed frames. In the future we intend to expand this capability in conjunction with our research into intelligent pre-caching of Web page content. In this way we hope to re-purpose content that we anticipate the client will require and target frames would fall into this category.
