DTD and Schema Work

Document Type Definitions (DTDs) may be represented graphically, and if we consider a proposed structure for the description of a software component interface we might use a DTD such as that shown in figure 1.

Fig. 1 A graphical representation of document type definition (DTD) of a software component

The same information may be represented as a text file:

<?xml version="1.0" encoding="UTF-8"?>

<!--A Sample Interface Specification DTD-->

<!ELEMENT INTERFACE2

(METHOD+, UNIQUE_ID, POLICY*, NAME, LOCATION, ABSTRACT, PARENT) >

< !ELEMENT UNIQUE_ID (#PCDATA) >

<!ELEMENT POLICY (#PCDATA) >

< !ATTLIST POLICY

TYPE (AUTHORISATION | OBLIGATION) "AUTHORISATION"

ORIGINATOR CDATA #REQUIRED

SOURCE CDATA #REQUIRED

TARGET CDATA #REQUIRED

ACTION CDATA #REQUIRED >

<!ELEMENT NAME (#PCDATA) >

<!ELEMENT LOCATION (#PCDATA) > !ELEMENT ABSTRACT (#PCDATA) >

<!ELEMENT PARENT (#PCDATA) >

<!ELEMENT MNAME (#PCDATA) >

<!ELEMENT INPUT (VALUE,TYPE,CONSTRAINT*) >

<!ELEMENT OUTPUT (VALUE,TYPE,CONSTRAINT*) >

<!ELEMENT NOTES EMPTY >

<!ATTLIST NOTES notes CDATA #REQUIRED>

<!ELEMENT VALUE (#PCDATA) >

<!ELEMENT TYPE (#PCDATA) >

< !ELEMENT CONSTRAINT (#PCDATA) >

It should be noticed that even this initial attempt at an extended interface definition includes much more useful information than existing IDL based descriptions, particularly any constraints on the input values. This interface specification forms part of a much larger component description document that includes resource requirement information, the software dependencies of the component and the location of the software for download etc.

There is one obvious drawback of the DTD-based approach, and that is the content of every element is a string, hence there is no mechanism for checking the type of any element or attribute supplied in the XML document. This is another driver for the development of new document description approaches based on schema. A schema is analogous to a DTD but is much more expressive, and of course uses XML to describe the structure of an XML document. There are currently a number of competing schema based proposals but as an example a simple schema based on the XML schema proposal may be written as:

<Schema xmlns="urn:schemas-microsoft-com:xml-data" xmlns:dt="urn:schemas-microsoft-com:datatypes">

<AttributeType name = "name" required="yes" dt:type="string" />

<AttributeType name = "address" required="yes" dt:type="string" />

<AttributeType name = "loc" required="yes" dt:type="string" />

<AttributeType name = "number" required="yes" dt:type="string" />

<AttributeType name = "account_number" required="yes" dt:type="string" /> <AttributeType name = "ORIGINATOR" required="yes" dt:type="string" /> <AttributeType name = "SOURCE" required="yes" dt:type="string" /> <AttributeType name = "TARGET" required="yes" dt:type="string" /> <AttributeType name = "ACTION" required="yes" dt:type="string" /> <AttributeType name ="TYPE" required ="yes" dt:type="enumeration" dt:values= " AUTHORISATION OBLIGATION"/>

<ElementType name = " name"> <attribute type = "name"/> </ElementType>

<ElementType name ="contract"> <attribute type ="number"/> </ElementType>

<ElementType name ="Address"> <attribute type ="address"/> </ElementType>

<ElementType name ="accountinfo"> <attribute type ="account_number"/> </ElementType>

<ElementType name ="Accountname"> <attribute type ="name"/> </ElementType>

<ElementType name ="location"> <attribute type ="loc"/> </ElementType>

<ElementType name = "POLICY" content ="mixed"> <attribute type = "TYPE"/> <attribute type="ORIGINATOR"/> <attribute type= "SOURCE"/> <attribute type= " TARGET"/> <attribute type = "ACTION"/> </ElementType>

<ElementType name ="Supplier" content="eltOnly"> <element type = "name"/> <element type ="Accountname"/> <element type ="contract"/> <element type = "accountinfo"/> </ElementType>

<ElementType name ="Client" content="eltOnly"> <element type= " name"/> <element type= "Address"/> <element type= "location"/> <group minOccurs="0"> element type= "POLICY" /> </group> <element type= "Supplier"/> </ElementType>

</Schema>
