Self-Organising Data Networks

Self-Organising Networks

After discussing the different reasons and motivations for data replication and caching we will, in the next two sections, discuss in some detail the algorithms used for data replication and caching. We will also introduce simulation models that have been developed, demonstrating the potential benefits efficient file distribution brings to CPs and ISPs. As both the algorithms are autonomous and dependent on the user request distribution they can be viewed as examples of self-organising networks.

Replication

In the replication scenario the CPs would like to replicate their services to the edge of the network (i.e. at the ISPs servers) so that a better QoS can be provided to the end users (figure 2). Depending on the point-of-presence of the CP there will be certain ISPs that are more attractive than others. For example, a CP in the USA with good US backbone connections may only consider replication into European or Asian ISPs, provided that the CP offers services in these regions.

Fig 2. In the replication scenario the content is copied to the edge of the network, i.e. the ISP servers, to which the customers directly connect.

Given the above scenario, we have built a mathematical model of the replication network. It consists of a number of nodes, each one being able to present either an ISP, a CP or both, which is the general case since a CP can be an ISP and vice versa. Assumptions are made about the average connection speed between the nodes. Furthermore, we make assumptions about the data request patterns and derive from it the server load by using standard queuing theory. We have assumed that the most important performance measure is the user perceived latency, since it also has an impact upon the QoS that can be provided to the customers. Other measures of interest may include the incurred financial cost.

Running the simulation model enables us to analyse different scenarios and for each one the average user-perceived latency. We adopt a view of the network as a whole and are interested in minimising the average latency rather than measuring the performance from the perspective of a single CP. This approach allows for a game theoretic analysis, some of which has been undertaken (see Olafsson [6]). In the present work we discuss two different adaptation algorithms for the optimisation of the average network performance.

The first is a 'greedy' algorithm, which consists of selfishly allocating resources without regard to the needs of other members of the network. While greedy algorithms are optimal for certain classes of problems (e.g. the minimal spanning tree problem), in practice they often only produce near optimal solutions. Greedy algorithms, however, are very fast and are normally used as heuristic methods. The greedy approach seems to be very well suited to our optimisation problem since the data which we use is delayed (i.e. the log files used in the optimisation represent past usage patterns and are not guarantees for future usage patterns).

The second adaptation mechanism is an evolutionary algorithm (EA). EAs are very popular adaptation engines due to their simple concept and wide applicability [7, 8]. The standard EA is a population-based search in which individual solutions compete with each other. During this competition process, solutions are allowed to exchange information with other solutions through operators such as mutation and crossover [9]. In order to achieve good results with EAs special care must be taken as to how to represent the problem and how to deal with the constraints the problem imposes [10]. In our case, for example, a constraint considered can be the ISP server disk space, which cannot be exceeded. Results from the usage of the two algorithms are presented in figure 3.
 

Fig 3. Presenting the performance of greedy and evolutionary algorithms. The objective is to minimise the user-perceived latency (plotted on the Y-axis). The simulation runs for 100 days.

The developed simulation model can help a network designer to find a configuration of replication scenarios, which provide the best overall network performance from the perspective of the user. Moreover, the provided adaptation mechanism is algorithmic in nature and can be automated, thus allowing the network to reconfigure or self-organise itself. This is in contrast with current practices, which largely require manual configuration.

Caching

The cache infrastructure toolbox discussed in this section has been described in Bilchev et al [2]. The model starts by analysing the current WWW usage patterns. We have identified that daily usage patterns typically consist of an underlying trend superimposed by a stochastic component. To model the underlying trend we have used a 'superposition' of periodic functions. Once the trend has been approximated the stochastic component is modelled as a series of Brownian motion processes (i.e. random walks). Two points are worth mentioning. Firstly, since the number of requested files is always non-negative we have to truncate all negative values to zero. Secondly, bursts in a positive direction are higher than bursts in a negative direction. To accommodate for this we have modified the variance in the random walk process so that positive deviations are higher than negative deviations. The last modification also has the effect of reducing the number of times the produced time series has to be truncated due to negative values. The produced usage pattern is appropriately represented to the cache network designer through a standard interface (figure 4a).

The next step is modelling the popularity distribution of the WWW page requests. There is significant evidence in the literature suggesting that the popularity distribution follows a Zipf's-like law, where the relative popularity of the ith most popular file is proportional to. The distribution has been implemented and appropriately presented to the cache network designer (figure 4b).

After developing the user community model we proceed with the cache proxy model. The cache proxy is modelled by Web content expiry statistics and it also implements a simplified caching algorithm. The expiry statistic models both the rate of change of Web pages, reflecting server assigned time to live (TTL), and cache purging due to stale data (i.e., cache assigned TTL). The model also implements the least recently used (LRU) cache replacement algorithm.

The simulation works as follows. The proxy cache receives requests for individual files. It checks if the requested file has already been registered in the cache before. If not, the file is time-stamped, registered in the cache and a miss is reported (i.e., this reflects downloading the file from the origin server and caching it). If the requested file has been registered in the cache before, the proxy checks the TTL. If the file has expired the proxy verifies whether the file has changed. If so, a miss is reported and the time stamp of the file is reset (this reflects downloading of the new version of the file from the origin server). If the file has not changed, a hit is reported and again the time stamp is reset.

Once the single proxy has been modelled, we can build meshes of interconnected proxy caches. To achieve this the simulation toolbox allows two caches to be linked together. We consider two types of links.

  • Parental links in which a miss is propagated to the parent cache and it is responsible for providing that file back either from its cache neighbourhood or from the origin server. On its way back the file is cached at each parental level.
  • Peer or sibling links, in which a peer proxy only checks if it has the file in its neighbourhood, but does not download it from the origin server in case of a miss.

Using the above-described links a cache network designer can build and simulate a number of caching infrastructures assessing their performance and expected benefits. In order to do that, the toolbox defines a number of performance measures, including request hit rate, byte hit rate, saved bandwidth consumption (figure 5) and saved pounds.
