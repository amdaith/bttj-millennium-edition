Modality Integrator

The next stage is to integrate the touch and speech modalities using the Modality Integrator. For a discussion of a number of possible approaches that may be taken, see the section 'Approaches to Multimodal Integration'. This component combines the semantics from the different modalities into a single semantic representation of the user's interaction. It contends with the ambiguity and errors which occur in each modality and, through unification, many hypotheses can be eliminated, leading to one or a small subset of possible interpretations.

The process begins by examining the speech semantics for references indicating that the user said 'this', 'that', 'there', etc. As discussed above, references are represented using a feature-value pair, where the value is a structure which indicates the category of the reference and possibly whether the user was referring to an object, fabric or position. The references are stored in a database of facts. Touch semantics are also stored, and the integration process continues by finding all possible combinations of speech and touch references that unify. Unification compares the category, type and value for each pair of references. If they are equivalent, as determined by the application, then they are unified. In the case where the user touches two or more times, then the number of combinations can be reduced by preserving the order of the speech references, and ensuring that the combinations retain this ordering. For example, consider the following interaction: "show me this on this" with the intention: transfer the fabric on palette (1) to 'Chair 1'. The example shows that there is only one possible combination, giving the following unification:

  • deixis:[cat:dem, type:fabric, value:'044']
  • deixis:[cat:dem, type:object, value:'Chair 1']

This approach also preserves the ambiguity when the user requests, "show me this on this" but actually touches first the sofa, then the chair, where the intention is to transfer the fabric that is currently on the sofa on to the chair. A set of possible combinations are then passed to the Dialogue Manager, whose task it is to disambiguate the combined semantics and finally understand the user's intention.

One of the problems inherent in the approach to unification we are using is that we are regarding each event with absolute confidence. While we may be quite sure that any touch events are reliable, speech recognition is far from reliable. Of particular concern is the occurrence of false-positive recognition of reference words such as 'this', 'that' and 'here', etc, where the user has said some other non-reference word. This may subsequently lead to incorrect integration, and the error being propagated throughout the system. One of the potential advantages of multiple modes of communication is that one can compensate for the weaknesses in others. Hence, a form of confidence score is required where confidence in decoded words, touches, and so forth, can be assessed and alternatives considered. The utilisation and manipulation of confidence scores is a pending research issue that will need to be approached in order to truly realise the potential of multimodal interfaces.

For further discussion on the processes involved in integration, see Churcher & Wyard [8]. For a discussion of the approaches and issues present in multimodal integration, see the section: 'Approaches to Multimodal Integration'.
