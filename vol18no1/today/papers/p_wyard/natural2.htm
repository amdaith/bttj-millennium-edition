The Natural Language Understanding Module

The recognised string output from the speech recogniser is processed by the Natural Language Understanding (NLU) component to give a semantic representation of what was said. The NLU component is robust to minor speech recognition errors, because it uses a localised slot-filling approach. Each slot scans the recogniser output from left to right, using its associated slot grammar to try to fill itself. (A slot grammar is simply a small grammar of all the phrases which can cause a slot to be filled, and the values which fill the slot.) Longer sequences of words fill slots in preference to shorter sequences. The slots may be nested, which allows a certain degree of relational information between entities to be captured. Phrases such as 'fabrics in green stripy linen' or 'red checked fabric for the sofa' are parsed into a single slot structure, as is a phrase such as 'this chair'. If multiple slots can be filled with equal likelihood from the same sequence of words, then multiple interpretations are returned in the semantics. This currently leads to considerable ambiguity, as a phrase like 'show me' can be used to refer to four functions: select fabrics, transfer a fabric onto an object, move an item of furniture, and move the user's viewpoint. This ambiguity is resolved by the dialogue manager after being unified with any touches made by the user. For further information on modality integration see Modality Integrator; for a brief description of the dialogue manager see Dialogue Manager.

Some examples may help to clarify typical input to and output from the NLU module.

"some red fabrics" -> [type:fabric, colour:red]

"green stripey fabric in linen" -> [type:fabric, colour:green, pattern:striped, material:linen_union]

"the red one" -> [salient:fabric, colour:red, deixis:[cat:ana]] (the salient feature is filled by "the" but the NLU knows that the salient item is a fabric because it parses the entire phrase. "one" is an anaphoric reference, which can be resolved by the DM).

"show me" -> [[function:select_fabric], [function:transfer_fabric], [function:move_user], [function:move_object]] (here we have a 4-way ambiguity which must be resolved in the DM).

"put this on this" -> [function:transfer_fabric, deixis:[cat:dem], deixis:[cat:dem, type:object]] (note that we have two deictic references in this example. The first is parsed as simply being of category demonstrative, while the second is also identified as being as of type object, since in this application one can only put things on furniture objects.
