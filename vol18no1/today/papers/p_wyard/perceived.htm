Perceived System Intelligence

This section highlights some of the mechanisms employed by the system to give the user the impression that it is an intelligent system. There are three main categories of response or behaviour: system initiatives, contextual help and response generation. The system is able to independently make suggestions to the user, and take control of the dialogue by taking the initiative. It is able to recover from user's errors by responding according to the current context, i.e. depending on what the user is trying to achieve. Thus responses can be context specific and help the user recover from errors. The response generation module generates these appropriate sentences.

System Initiatives

It is our goal to create a mixed-initiative system, in which the system is not a dumb slave but is able to take appropriate initiatives. To date, through the creation of a behaviour model, we have created two rudimentary system 'characters': the Designer, to provide expert advice on interior design, and the sales person, to gently persuade the user to buy. Each has a set of rules which tell it which initiatives to take in which dialogue contexts and given certain behaviour from the user. Additionally, a pause in the user's input can trigger a system initiative.

The behavioural model works by considering the dialogue context at each turn and determining whether an initiative can be triggered given the current context. This allows the system to modify a user's request, ignore it, and to trigger suggestions at a later stage. This basic model can be built upon so that initiatives are triggered on other cues, such as the current selection of fabrics, whether the user has ignored the system's advice or taken it and so forth.

An example will illustrate: the Designer may initially ask which broad style of furnishings the user would like, and perhaps suggest the currently most popular style. Once the user has selected one class of fabrics, say curtains, the Designer may suggest some suitable fabrics for another class. If the user has chosen fabrics which do not suit well according to its algorithms, it may suggest that the user considers a 'deeper red on the sofa', for example. If the user is vacillating between two different curtain fabrics, the Designer may offer its opinion, and so on.

Contextual help (error recovery)

This includes error recovery in the face of recognition errors, or where a verbal reference cannot be resolved, or where a touch input is missed. It is driven by the fact that the system knows that there has been an input, but a full interpretation cannot be made because required information is missing. The help or error-recovery output is tailored both to the task which the user is currently engaged on, and to the recent dialogue history relating to the error.

For example:

U: "Try this one on it."

S: [cannot resolve "it"]

S: "Which object do you want to transfer the fabric to?" (it knows that the task is transfer_fabric)

U: "This one." [user misses the desired object with his touch]

S: "Which object do you mean?" (doesn't repeat the words about transferring fabric).

S: "Please touch one of the objects clearly."

This module is also able to help when the user tries to take some "illegal" actions in the VW, e.g. it will tell him that he cannot put cartouche stripe on the walls, because it is an upholstery fabric.

Response Generation

This is a straightforward component at present, which generates the output text for the Virtual Assistant after any system initiatives or contextual help have been generated. It uses a simple generation grammar and can generate longer or shorter responses depending on the context. For example, if the system has to repeat a question, then it can make it more informative; when the user has gained knowledge of interacting with the system, then terse responses can be used instead. Hence, the response generation module is able to tailor responses both to the dialogue context and to the user's experience of the system.
