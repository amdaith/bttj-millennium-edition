Process Engineering for the Alliance Partners

The Alliance Process and Data Model

Within the Advanced Operational Solutions Unit in BT, we have had experience of a number of business engineering tools. Based on this experience it was agreed that an appropriate tool would help reduce the time taken to develop an approach, as it would have built-in a lot of the basic process engineering concepts. The benefits required of such a tool were as follows:

  • repository-based, allowing sharing of designs,
  • allows integration of Processes, Systems, Organisation & Data,
  • easy to use,
  • easily customised,
  • provides Change Control,
  • interfaces with process simulation software.

A review of existing work by another team within BT identified a number of suitable tools, including SA/BPR from Popkin Software and Systems, and ARIS from IDS Scheer. SA/BPR was chosen for this particular project, as it was found to be particularly easy to learn and use.

The tool was used to develop the Alliance Process and Data Model (APDM), with the intention of building a generic business model which individual Alliance Partners could use as a foundation for their own business models. This provided a 'launching pad' from which the Alliance Partners could rapidly develop the key processes required to run their business.

The intention was to develop this tool in three phases. The first phase was to customise the SA/BPR tool to help with organisational and process design enabling the team to create an encyclopaedia of best practice processes. This work was completed in December 1998 and has been used in a number of BT's Alliance Partner organisations (see sunrise case study). The second phase, under way now, will look at linking the processes with system functions and organisational data so that it is possible to determine the impact of process changes on OSS and where data should be stored. The final phase is to look at simulation of the processes so that the tool can be used to determine where potential bottlenecks are and to perform 'What if' type analysis on existing processes.

In completing the first phase of the development, the SA/BPR tool was customised to ensure that all relevant organisational, functional and workflow information could be captured, and a considerable base of process engineering knowledge was built up. This provided a framework within which to assist not only the Alliance Partners but also BT to:

  • make use of best-practice methods;
  • reduce the time taken to develop processes;
  • increase the level of reuse of parts of a process;
  • be consistent across products;
  • provide a simple means of communication to end users and
  • be adaptable to the changing needs of an organisation.

It should be made clear that although the SA/BPR tool was used to support this development, the methodology is not specific to any one tool. It will also be migrated to other tools such as ARIS, which may offer a wider set of business modelling tools.
