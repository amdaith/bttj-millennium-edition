FreeUnet Work Packages

The following sections describe some of the work using and developing FreeUnet at the moment.

Core Based Tress Multicast routeing

The FreeUnet project has generated an implementation of the IETF Core Based Trees multicast routing protocol [12, 13, 14]. This is a world first, and the software has been made available [11] to the internet community as Open Source for the FreeBSD operating system.

Core Based Trees is a model for constructing bidirectional trees of routes between the members of a multicast group. The currently common unidirectional tree algorithms send changes in tree structure back to the 'root' for propogation back down the tree, while bidirectional trees propogate changes directly to their destinations. Core Based Trees also hold less state in each router than unidirectional tree algorithms (only one entry per multicast group). The combination of low state and less dependance on a tree 'root' makes Core Based Trees a highly scalable solution especially for large multicast networks.

Dynamic QoS

FreeUnet supports dynamic Quality of Service (QoS) configuration, a first on an IP network. The QoS used is Open Source implementation of Class Based Queuing (CBQ) [15] from Sony Computer Science Laboratories [16]. We are extending this implementation to automate real time dynamic configuration and are adding the ability to deploy a QoS policy across a family of routers from one host.

Class Based Queuing allows the creation of hierarchical classes of traffic, a facility not yet available in most commercial routers. An example application of hierarchical classes would be the creation of a parent class in the core routers of a network for traffic between two virtual private networks (VPNs). The access routers linking the VPNs to the core would further refine this class into priority applications and flows, ensuring the facility is not wasted on low priority traffic. The advantage of this model is that only access routers need an understanding of how to shape outgoing traffic, which reduces the scaling issues of configuring large networks with QoS rules.

We have added a tool to the CBQ system to monitor throughput per class on any outgoing interface of a router. Using Sony's cbqprobe tool the CBQ statistics are transmitted to multicast groups, which are monitored by our software on a FreeUnet Web server. Users anywhere can then view the CBQ statistics in graphical form using Java applets from the Web server. One person developed this tool within a week of first exposure to the Sony CBQ distribution, a demonstration of the flexibility of Open Source software distribution.

MONTI - real-time traffic flow measurement

MONTI (monitoring of network traffic information) is another world first, based on the RTFM (real-time traffic flow measurement) IETF standards [17]. A MONTI client on a network user's host measures traffic flows and makes its measurements available as persistent text for automated collation. What the client monitors is defined by RTFM rulesets, which can either be added to or installed with the client, or pushed to clients using SNMP (Simple Network Management Protocol) [18] from a MONTI RTFM manager. The measurements are also available as real-time WWW pages direct from the host using the MONTI client's http server and Java applets, as in figures 2, 3 and 4.

IP v6

The purpose of this work is to gain experience in an intranet migration from IPv4 to IPv6 [19], and at the same time to offer FreeUnet clients the possibility of having a first taste on IPv6. We adopt a dual stack approach to the migration problem in order to ensure smooth transition and interoperability with legacy systems.

Three steps were defined in order to bring to term the migration.

Firstly all end systems and the Server Farm have been migrated to dual stack.

Secondly, we have allowed connectivity between LANs and Server Farm using two different transition mechanisms, the Tunnel Broker (figure 5), [20] and 6to4 [21] mechanism. The Tunnel Broker is a tool that allows automatic IPv6 in IPv4 tunnels between isolated dual stack clients and the IPv6 world.

Fig 5. IPv6 Tunnel Brokers

The 6to4 tool is applicable for interconnection of isolated IPv6 domains in an IPv4 world. The egress router of the IPv6 domain creates a tunnel to the ingress router of another domain. The IPv4 endpoints of the tunnel are identified in the prefix of the IPv6 domain. This prefix is made up of a unique 6to4 TLA (2002::/16) plus an NLA that identifies the site by the IPv4 address of the translating egress router.

At this point any isolated dual stack client (using Tunnel Broker) or isolated IPv6 LAN using the 6to4 tools inside BT Intranet, can access to FreeUnet IPv6 services (for the moment is IPv6 Web browsing and that in the future will include IPv6 audio and video).

The third and last step of the migration is to migrate FreeUnet core routers to IPv6 to allow native IPv6 connections.

Dialup services

A PC router based on FreeBSD OS plays the role of Network Access Server (NAS) for FreeUnet. Our NAS allows dial-up clients to connect to FreeUnet over telephone lines and 56 K modems. Apart from applications like e-mail, Web, etc, we also provide value-add features to dial-up clients like access to multicast traffic and special QoS features. Special low-bandwidth video and audio multicast and unicast streams are available on our Web Farm for use by dial clients while the particular streams are also QoS protected in the FreeUnet core by Class Based Queuing (CBQ).

The forwarding of multicast information to dial-up hosts by the NAS is a new development not available commercially. Previously multicast access over dial-up links tended to use a proxy to join the multicast group on the client's behalf - this worked and prevented state-related problems between multicast servers (created by multicast implementation assumptions about the availability over time of links), but does not scale well for many hosts.

ADSL services

In addition to its core network FreeUnet also features a fully routed access network (figure 6). ADSL access is simulated using asymmetric ATM PVCs (permanent virtual channels). This mid-band network provides access to FreeUnet core network to both single hosts and 'home' networks. A Video On Demand server (VoD) connects directly into this access network acting as an example of content provider. Routers in the access network are connected using an ATM switch (Cisco 1010) through ATM PVCs. This access network is attached to the core network through 1000 BaseT (Gigabit Ethernet) interfaces. QoS and multicast are supported on this network as in FreeUnet core and thus provide seamless services across both of them. IPv6 support in the form of dual stack is also in the pipeline.
