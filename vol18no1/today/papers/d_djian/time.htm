Towards Human-Centred Intelligent Systems: The Intelligent Assistant

Time Management

Diary assistant

The Diary Assistant helps the user with time management by maintaining a schedule of tasks. The user is able to enter and edit tasks, move tasks from one day to another, save and load particular day sequences, and invoke the scheduling capabilities of the assistant. The main interface to the Diary Assistant is designed to look like a standard paper diary, with each day divided into half hour slots starting from 9:00 through to 5:00, as shown in the video clips below. In the display, the duration of each task is given in parentheses beside its description, in the form hours:minutes.

Users can specify preferences for the start time, duration and deadline of a task using terms that are interpreted as fuzzy predicates. At present, the following fuzzy terms are supported:

  • for time preferences, morning, afternoon, early morning, late morning, early afternoon, late afternoon, around t and about t where t is a crisp time, and when using the global scheduler (see below), early this week and late this week;
  • and for durations, around d and about d where d is a crisp duration.

The function denoted by each of these predicates is predefined. As an illustration, the fuzzy function for interpreting the morning predicate is shown in figure 9 (at times other than those displayed, the value is 0, and the preference is not satisfied).

Fig 9. Fuzzy function for 'morning'

When allocating time-slots to tasks, the system attempts to maximise the satisfaction of the user's preferences as supplied when the tasks were entered. When a task is moved to a new day, the scheduler uses the original preferred start time, so the time-slot allocated to the task on the new day may differ from previously. This is shown in the following video (figure 10).

 

Fig 10. Effect of fuzzy function

The Diary Assistant incorporates two schedulers - a global scheduler for allocating time-slots to a set of tasks so as to maximize overall preference satisfaction, and a local scheduler that makes minimal adjustments to an existing schedule when adding a single new task. The global scheduler uses a standard AI depth-first search algorithm with backtracking, and heuristic guidance to improve efficiency. The search uses heuristics in two ways - for defining the order in which tasks are considered and the order in which allocations to tasks are explored. First, tasks are ordered from most constrained to least constrained, where one task is more constrained than another if there are fewer possible time-slots that satisfy the user's preference for that task. Second, when considering a single task in the context of a partial schedule (an allocation of time-slots to the more constrained tasks), the possible time-slots are explored in order of preference satisfaction.

The following video (figure 11) illustrates how the local scheduler makes adjustments to the schedule so as to satisfy the user's preferences. In this example, a task with a fuzzy preferred start time is moved to allow a new task to be included in the schedule, and a task with an approximate duration is shortened to accommodate an additional task.

Co-ordination in the Intelligent Assistant

Co-ordination in the IA is necessary first to avoid overloading the user with information from many assistants at the same time - this type of co-ordination essentially involves managing the interaction between the assistants and the user. A more interesting aspect of co-ordination involves proactive behaviour - this refers to the system itself performing tasks on behalf of the user that require the action of more than one assistant (comprising simple plans of action). An important aspect of this type of co-ordination is the performance of actions at appropriate times.

The IA includes a specialist Co-ordinator Assistant (CA) which manages the interactions between different assistants and between the user and the assistants. To manage the interaction between the user and the IA, the CA maintains, based on information supplied by the Diary Assistant, information about whether the user is:

  • accepting phone calls,
  • accepting e-mails,
  • accepting interruptions (from any assistant)

This information (see figure 12) is used, for example, by the Telephone Assistant when responding to an incoming call. The status can be updated directly from the user interface - if the user sets status interruptible, the state switches to accepting phone calls and e-mails automatically (and similarly when setting status to non-interruptible, the state is set to refusing phone calls and e-mails).
